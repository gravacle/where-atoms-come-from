1. ESCAPE (3).  THE WRITER GROUP IS NON-ABELIAN, SO A WRITE-LOOP LEAVES A HOLONOMY.
   Group generated by ALL EIGHT searched writers (4 for R1, 4 for R2), phases kept:
   |G_W| with phases = 64;  its image on configurations has order 4;  KERNEL order 16
   The kernel is the set of write-histories that return the configuration to where it
   started.  ITS ELEMENTS ARE THE HOLONOMIES.  Identify them:
   holonomy elements found: I x {+1,+i,-1,-i}, R1 x {+1,+i,-1,-i}, R1.R2 x {+1,+i,-1,-i}, R2 x {+1,+i,-1,-i}
   EXACTLY: HOLONOMY GROUP = <R1, R2> x PHASES.  THE HOLONOMY OF A WRITE-LOOP IS A PRODUCT
   OF THE RECORDS THEMSELVES, TIMES A CONSTANT PHASE.  History adds no new object.

   THE CONCRETE LOOP.  Write record 1 with Xbar1, then write it again with Ybar1:
   both are admissible writers of R1 (part 1).  The configuration returns to its start.
   NET OPERATOR = -i * R1  -- the RECORD OPERATOR itself.
      configuration    <holonomy> (complex)  phase-stripped   is it a fn of s?
           (-1, -1)         +0.0000+1.0000i         -1.0000   YES -- it IS s_1
            (1, -1)         +0.0000-1.0000i          1.0000   YES -- it IS s_1
            (-1, 1)         +0.0000+1.0000i         -1.0000   YES -- it IS s_1
             (1, 1)         +0.0000-1.0000i          1.0000   YES -- it IS s_1
   So the ONLY thing a write-history leaves behind is (i) a record value -- a configuration
   functional, which cancels by part 2 -- or (ii) a global phase, which is a constant and
   is therefore record-blind.  ESCAPE (3) CLOSED, exactly.
